# 生物图鉴（站内）口径

页面把 `guides.js` 的 167 条手写条目与 `monster-spawn-tiers.js` / `monsters-difficulty.js` / `horde-buildings.js`
三份生成数据合并成一份 200 条目录，规则写在 `src/client/monsters.ts` 的 `buildCatalog()`，
`npm run verify:monsterguide` 锁住结果。生成数据的推导见 `docs/monster-handbook.md`，
逐怪梯度表见 `docs/monster-spawn-tiers.md`，逐建筑尸潮见 `docs/horde-buildings.md`。

## 1. 三档状态

| 状态 | 条数 | 判定 | 在页面上的位置 |
|---|---:|---|---|
| `spawns` 会刷 | 93 | 四来源至少命中一个，或原版僵尸变体，或 NPC 克隆体 | 怪物 72（T1–T4 / 全图 28 / 深渊 5）+ 动物 21 |
| `unimplemented` 确认不会生成 | 60 | 区域刷怪器 / 模组自然刷 / 天数尸潮 / 尸潮建筑 全空 | 未实装 tab 第一档 |
| `unconfirmed` 来源未确认 | 47 | 包内注册名存在，但四个来源都扫不到 | 未实装 tab 第二档 |

后两档合计 107 条，按需求「不参与其他筛选」：不进 T1–T4 分组、不进数值查询、检索只在 tab 内生效。

标题那 93 条会刷的实体里，**21 只中立动物已拆成独立页**（`#/creatures/animals`），怪物清单只剩 72 条：
T4 分组从 34 降到 15、全图分组从 30 降到 28。动物不分组、不做详情页，行里给名字 + 模组 + 刷新条件 + 中立徽章；
其中 6 种（大象 / 灰熊 / 狮子 / 犀牛 / 鳄鱼 / 野猪）在属性脚本里有数值，按原值列三个数，其余 15 种只给刷新规则。

## 2. 合并时踩到的三件事

1. **手写 167 条里有 50 条不在生成数据里** —— 大部分在模组 jar 的 `lang/zh_cn.json` 里能找到注册名（`zombie_extreme:chainsaw`、`spore:leviathan`、`deaceased:stunner`…），
   所以不能当「不会生成」，进 `unconfirmed`，详情页明确写「不给数值矩阵」。
2. **3 处 id 拼写差异**：手写 `hordes:zombieplayer` / `huskplayer` / `drownedplayer`，包内注册名带下划线（`hordes:zombie_player`）。
   不归并会出现 3 对重复条目，`ID_FIXES` 负责修正。
3. **尸壳 / 溺尸不是未实装**：它们是原版僵尸变体，刷怪由原版逻辑接管，`VARIANT_OF` 让它们跟着僵尸进「全图」组并标注证据。

## 3. 数值矩阵的段与行

详情页矩阵按场景分段，每段三行（简单 / 普通 / 困难），四列指标：

| 段 | 数据来源 | 显示条件 |
|---|---|---|
| 野外 · 无区域加成 | `monsters-difficulty.js` `wild` | 始终 |
| 城区 T1–T4 | 同上 `city[T*]` | 只显示该怪实际会刷的梯度；全图怪四档全显示；深渊专属怪整段不显示（深渊规则只看维度，不吃城区倍率） |
| 天数尸潮 | 同上 `horde.{normal,hard}` | 只在表的怪 |
| 建筑尸潮 T1–T4 | 同上 `horde.city[T*]` | 只显示它出现的建筑所属梯度 |
| 深渊 / 深渊尸潮（推算） | 同上 `abyss` | 只对 `spore:*` 或深渊刷怪清单里的怪；深渊尸潮那行标注「包里尚未配置」 |

列：生命（半心）· 护甲（半甲）· 攻击（铁剑）· 对玩家（半心）。图标用 `public/images/ui/stat-*.png`（9×9 / 16×16 原图，CSS 放大 + `image-rendering: pixelated`），
满版表示有值，空版表示该项为 0 或无数值。

「具体数值」按钮弹出的快览只给**困难**这一列：野外 / 城区 T1–T4 / 天数尸潮 / 建筑尸潮 T1–T4 / 深渊，覆盖「困难 T1 尸潮」这类确认。
注意两种尸潮不同源：**天数尸潮不吃区域加成**（僵尸困难 40），**建筑尸潮按建筑所在区域叠一层**（T1 派出所僵尸困难 50）。

## 4. 列表怎么读

行首是生物图标：有立绘（手写条目的 MC百科图）就显示立绘；没有的按类别给图形——
敌对用骷髅、NPC 用人群、中立用爪印，未实装那两档用灰色，避免和会刷的怪抢注意力。
72 条怪物里 65 条有立绘，107 条未实装里 102 条有，动物 21 条全没有（包里就没有动物立绘）。

`T1 T2 T3 T4` 四个点是固定槽位，实心＝该梯度会刷，色阶只用一种红色从 0.45 到 0.92 的浓淡表示危险递进；
不挑区域的标「全图」，只在深渊维度刷的标「深渊」，未实装的两档不画点阵、右侧写「无梯度」。右侧数字是 `attribute.js` 原值（基础生命 / 护甲 / 攻击），场景化的数字走「具体数值」按钮。

长列表不再一次塞进 DOM：怪物 200 条、枪械 177 条、载具 118 条都走 `src/client/lazy.ts` 的滚动加载
（先渲 40 条，滚到哨兵再追加 40 条；行直接插进 `.list` 容器，不加包裹层，所以 flex/grid 的 gap 与两列网格不变；
浏览器不支持 `IntersectionObserver` 时退回一次全渲染）。怪物页「未实装」两档、图鉴通用列表都是同一个实现。

NPC 详情页的交易清单超过 8 条时默认只显示前 8 条，底部一个「展开全部 N 项 / 收起」，按钮复用 `.quote-toggle`。

URL 参数可直接分享筛好的视图：`#/creatures/monsters?t=T1&th=灾厄`、`#/creatures/monsters/unimplemented?th=真菌`；
梯度 chip 的取值是 `T1`–`T4` / `全图` / `深渊`。

## 5. 字体与图标

界面骨架换成**缝合像素字体 Fusion Pixel 10px**（OFL-1.1，(c) 2022 TakWolf，许可证在 `public/fonts/OFL.txt`）：
导航、标题、徽章、chip、表格数字、梯度标签、数值按钮走像素字；正文、刷新条件、打法、来源仍是系统字。
这是部署版验证过的拆分——它自己先全站用像素字，最后强制把 body 改回系统字，只留下 UI 那批选择器。

三个落地要点：

1. `font-synthesis: none` + `-webkit-font-smoothing: none` + `text-rendering: geometricPrecision` 只加在像素字那批选择器上，
   否则 108 处 `font-weight: 600–900` 会合成假粗体、或者把系统字的抗锯齿一起关掉。
2. 这套字只有 400 一个字重，所以层级靠字号与颜色，不靠加粗。
3. 10px 是设计尺寸：梯度标签压到 10px、表格与属性数字压到 12px，避免 12.5/13.5 这种非整数缩放糊边。

HUD 指标图标（`public/images/ui/stat-*.png`）与像素字是同一套视觉：满心/半心/空心、满甲/半甲/空甲、铁剑。
**单位对齐游戏内 HUD**：游戏里一颗满心 = 2 点生命、一格满甲 = 2 点护甲，所以列表与矩阵里一律用**半心 / 半甲**，
一个图标 = 1 点，跟旁边写的原始数值（僵尸 20 血、护甲 2）严格一致；用满图标会让人把血量读成两倍。
半图标的另一半是深色，压到 17px 后直接放深色底上会看成一根竖条；这里不加底衬，靠旁边的数值与表头文字标签读它。

## 6. 主题与浮动件

- **数值按钮**在深色主题下曾出现「白底白字」：浅色主题的白底覆盖 `.num-btn` 时漏了 `[data-theme="light"]` 前缀。
  现在所有浅色覆盖都必须带前缀，断言里有一条专门守这个（裸 `.num-btn { background:#fff }` 会被判失败）。
- **音乐按钮**（`#musicFab`）从「按内容栏居中」改成 `right: 0` 贴屏幕右边缘，纵向位置不变；
  音乐面板 `.music-panel` 仍按内容栏居中，两者不再共用同一套定位。

## 8. 怪物数值手册（`#/creatures/monsters/stats`）

指南版有整页「怪物数值手册」，合并时连数据一起丢了（`GUIDE.monsterStats` / `monsterHandbook` 在当前
`public/data/guides.js` 里 0 处）。现在按同一信息密度重建，但不再另造数据：

| 块 | 来源 |
|---|---|
| 四格统计（实体 / 最高生命 / 最高护甲 / 最高攻击） | `monsters-difficulty.js` 的 `entities` 现算 |
| 速查 5 条、倍率层 9 行、区域标签 4 行 | 编辑内容，以 `docs/monster-handbook.md` §0 / §3.2 为准 |
| 133 行实体表（11 列、可搜可排序） | `entities[*].base` + `wild.easy/hard.toPlayer`，刷怪列取梯度数据的 `status` |

- 口径说明写在 hero 里：页面目录 200 条 = 会刷 93 + 未实装 60 + 来源未确认 47，本表只覆盖 133 条实体。
- 「简单 / 困难」两列是**怪打向裸装玩家**的伤害，不是血量倍率 —— 页面上明写了这一句，避免和矩阵混读。
- 不新增视觉：统计借用 `.stat-grid/.stat-box`，速查借用 `.handbook-rule`，表格借用 `.data-table`；
  只补了排序按钮 `.ms-sort` 与 11 列宽表 `.ms-entities`。
