# 管理员登录与在线换图

站长用唯一账号登录后，可以在站内任意页面直接把图片换成新图（自动转 WebP、存入对象存储），换完立刻全站生效，可回退上一版或恢复原图。

## 1. 配置

三件套都走环境变量（Zeabur → 服务 `wzsj-atlas` → 环境变量）：

| 变量 | 作用 | 说明 |
| --- | --- | --- |
| `ADMIN_EMAIL` | 管理员账号 | 登录框不校验邮箱格式，写 `admin` 也行；比较时忽略大小写 |
| `ADMIN_PASSWORD` | 管理员密码 | 只存在环境变量里，不入库、不可注册第二个管理员 |
| `DATA_DIR` | 数据目录 | 默认优先 `/data`（挂载点），没有就用容器盘的 `.data/` |

**挂载卷**：Zeabur 给 `wzsj-atlas` 挂一个卷到 `/data`（当前该服务没有卷）。不挂也能跑：容器盘上的 SQLite 每次部署都会清空，但启动时会从桶里的 `public/admin/state.json` 回灌，覆盖记录与管理员会话都不会丢。

## 2. 用法

1. 设置页 →「管理员登录」→ 输入账号密码（社区页的「登录」按钮是同一个入口）。
2. 登录后，站内每张可替换的图片右上角出现「换图」小按钮。
3. 点按钮 → 选图 → 服务端转 WebP 并回传预览，同时显示新图尺寸、体积、与原图的比例偏差（差超过 10% 会标黄警告）。
4. 「确认替换」写入；不想动就关闭弹层。弹层里还能「回退上一版」「恢复原图」，底部列出最近 3 个版本。
5. 退出：设置页里点「管理员：<账号>」确认退出。

## 3. 为什么需要一层服务端覆盖逻辑

站点图片有两套源：

- `public/data/guides.js` 等数据文件里的 `./images/…`、`/images/…`：构建时被改名成 `<名>.<8 位内容哈希>.webp`，服务端按 `immutable, max-age=31536000` 发一年。
- 数据里的 `/media/images/…`：由 `/media` 代理从 RustFS 取，同样是长缓存。

所以「直接覆盖桶里那个对象」对第一类引用完全无效——浏览器请求的是带哈希的文件名，而且 Cloudflare 边缘已经把旧字节缓存了 1 年，origin 改 `no-cache` 也换不掉已经进边缘的副本。

现在的做法：

1. 请求进来先把路径剥回**逻辑路径**：去掉 `?v=`、去掉 `/media/images` 前缀、去掉 8 位指纹哈希。
2. 命中覆盖表 → 从 `public/overrides/<sha16>.webp` 取新图返回，**原图与桶里原对象一个字节都不动**。
3. URL 上带 `?v=<10 位内容哈希>` 的请求发长缓存（URL 变了就等于新资源）；不带版本串的（CSS 里直接写死的那几张）发 `no-cache` + `ETag`，让浏览器每次复核。
4. 服务端在首屏之前用同步脚本 `/data/image-versions.js` 把「逻辑路径 → 版本号」发给页面；`src/client/image-versions.ts` 在模块求值期把它写进所有 `WZ_*` 数据与 `seed`，所以页面地址天然就是带版本串的新 URL，**不需要等异步请求，也不会晚于首次渲染**。
5. 换图成功后 `setImageVersion()` 同步改写内存表、数据对象和已渲染的 DOM，当前页面立刻显示新图，不用刷新。

## 4. 数据存在哪

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 覆盖 / 会话 / 审计 / 失败计数 | `$DATA_DIR/admin.db`（SQLite，WAL） | 内置 `node:sqlite`，不需要编译原生模块 |
| 整份状态镜像 | 桶里 `public/admin/state.json` | 每次改动 400ms 合并写一次；本地库为空时启动回灌 |
| 换图产物 | 桶里 `public/overrides/<sha16>.webp` + 本地 `$DATA_DIR/overrides/` | 按内容 sha 命名，同图重复上传不会重复占空间 |

每张图保留最近 3 个版本，更早的连同对象一起删掉。「恢复原图」只是删掉当前指针（历史仍可查），页面立刻回到构建产物里的原图。

## 5. 边界

- 只允许替换 `/images/**`（怪物、枪械、附件、建筑、载具、材料、指南插图、封面、UI 图）。`/textures/**`（728KB 精灵图集，换掉等于毁掉 2000+ 图标）、`/icons/**`（SVG 图标）、`/fonts/**` 不在可换清单里。
- 输入限 JPG / PNG / WebP / AVIF，单张 ≤ 10MB；输出长边 ≤ 2048、WebP 质量 90、保留 alpha。
- **CSS 里直接写死的 8 处图片地址拿不到版本串**（`page_creatures_bg.webp` 与 6 个半点制图标）。如果替换它们，已经进 Cloudflare 边缘的旧副本可能要等 TTL 或手动 purge 才会更新——这是「不换 URL 就换不掉边缘缓存」的必然结果。
- 单副本假设：本地 SQLite + 整份镜像在单 pod 下是自洽的；如果以后把服务扩到多副本，镜像会互相覆盖，需要改成共享数据库。
- 社区账号与管理员是两套会话：`wz_session` 是社区账号，`wz_admin` 是管理员；`/api/me` 两个身份都回。

## 6. 验证

```bash
npm run verify:admin        # 35+ 条契约断言（含运行时路径归一与版本串）
npm run verify              # 构建 + tsc + check:assets + verify:fingerprint + verify:admin
```

真机验证脚本（本地起服务后可用）：注册登录 → `/api/admin/image/preview` → `commit` → `GET /data/image-versions.js` → 取图应带 `X-Image-Override: 1`；删掉 `$DATA_DIR/admin.db` 重启，覆盖与登录态应从桶里回灌。
